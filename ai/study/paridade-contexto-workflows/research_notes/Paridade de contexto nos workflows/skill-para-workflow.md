## O que o starter e as skills exigem ao converter um skill, e onde isso diverge do código

### Takeaway

Converter é um processo de seis passos, obrigatório na skill `skill-to-workflow` e resumido no livro `docs/authoring/02-convertendo-skills-e-subagents.md`: inventário, cada decisão do modelo vira regra em código, mapeamento para `ctx.agent` / `ctx.parallel` / `ctx.pipeline` / `ctx.exec`, checklist de custo com estimativa por caminho, geração com teste offline, relatório do que ficou de fora. ## Como `argument-hint` e os args de slash command chegam ao workflow, e se `--review` / `--interview` viram dado

### Takeaway

`argument-hint` não é schema e não chega ao runtime. No Claude Code o texto depois de `/nome` vira string (`$ARGUMENTS` ou `$N`) colada no prompt; o modelo interpreta. No kit, o script lê `ctx.args`, um objeto JSON validado por Ajv contra `meta.argsSchema` antes de qualquer etapa. `--review` não é flag do `wf`. Vira ramo de código só se o objeto trouxer um campo enum, por exemplo `mode: "review"`. Quem monta esse objeto, no chat, ainda é o modelo da tool `start_workflow`; no terminal, é quem passa `--args`.

### Cited Findings

- Doc de skills do Cursor espelhada no estudo (`agent-skills-guide.md`): frontmatter reconhecido é `name`, `description`, `paths`, `disable-model-invocation`, `icon`, `color`, `metadata`. Não há campo `argument-hint`. `disable-model-invocation: true` inclui a skill só quando o usuário digita `/skill-name`. — [agent-skills-guide.md](file:///home/rodrigo/Workspace/ai-study-library/ai/docs/cursor/skills/agent-skills-guide.md)
- Doc de skills do Claude Code: `argument-hint` é "Hint shown during autocomplete", exemplo `[issue-number]` ou `[filename] [format]`. Não é parser. `arguments` declara nomes posicionais para substituição `$name`. `$ARGUMENTS` é o texto inteiro; `$ARGUMENTS[N]` e `$N` são o argumento N com quoting de shell. Sem placeholder, o Claude Code acrescenta `ARGUMENTS: <value>` ao fim do conteúdo. — [extend-claude-with-skills.md](file:///home/rodrigo/Workspace/ai-study-library/ai/docs/claude-code/skills/extend-claude-with-skills.md)

## Onde MCP e CLI são passo fixo, e o que o agente local do SDK faz com shell e MCP

### Takeaway

CLI que o workflow mesmo dispara é `ctx.exec(command, args)`: sem shell, argv separado, exit code e cauda de saída; o script decide o próximo passo e a chamada gasta zero token de modelo. Chamada MCP nomeada não existe na API do `ctx`. `mcpServers` e a tool `mcp` entregam a família MCP ao modelo, que escolhe a tool. O kit usa `customTools` do SDK só para `submit_result`. Shell do agente (`tools` contendo `"shell"`) é turno livre; shell do script é `ctx.exec`.

### Cited Findings

- `ctx.exec`: "Runs a command (no shell: `command` and its `args`)". Devolve `{ ok, exitCode, timedOut, tail, error? }`. `tail` são os últimos 32768 caracteres de stdout e stderr na ordem de chegada. Timeout: SIGTERM no grupo, SIGKILL dois segundos depois; default 10 minutos via config `execTimeoutMs`. Falha, timeout ou programa ausente é resultado, não exceção; cancelamento mata o processo e lança. Resume roda o comando de novo: `exec` não entra no journal. `scrubSecrets: true` tira do ambiente variáveis cujo nome contém KEY, TOKEN, SECRET ou PASSWORD. — [workflow.ts](file:///home/rodrigo/Workspace/cursor-workflows-starter/packages/runtime/src/runtime/workflow.ts)
- O livro manda todo comando do workflow (testes, `git`, `gh`, `glab`) por `ctx.exec`. Exemplo medido como correção: `bash -lc` carregou o perfil de login e quebrou o npm; `runTests` passou a `bash -c` herdando o ambiente de quem chamou. — [01-escrevendo-workflows.md](file:///home/rodrigo/Workspace/cursor-workflows-starter/docs/authoring/01-escrevendo-workflows.md); [verificacoes-locais.md](file:///home/rodrigo/Workspace/cursor-workflows-starter/docs/research/verificacoes-locais.md)
- Mapeamento da conversão: "Script called by the skill (lint, tests, build) → `ctx.exec`". Efeito externo depois das checagens, em código. — [SKILL.md](file:///home/rodrigo/Workspace/cursor-workflows-starter/skills/skill-to-workflow/SKILL.md)
- `AgentCallOptions.mcpServers` é `Record<string, McpServerConfig>`, por etapa. `tools` é allowlist. ### Inferences

- Inferência, ramo `--review` do alvo descrito (skill ausente; forma do pedido): o script escolhe o modo pelo enum, dispara os CLI de inspeção com `ctx.exec`, restringe `mcpServers` ao servidor daquele banco, pede ao agente um objeto cujo schema lista as categorias de achado, e roteia esse objeto em código (o que vira relatório, o que pede outra rodada, quando parar). Julgar se um achado procede continua no `ctx.agent`. Redigir prosa longa no schema mecânico é o que o checklist manda não pedir.
- Inferência, ramo `--interview`: se o corpo do skill for diálogo aberto, a regra escrita é não converter e deixar o skill. Se as perguntas forem uma lista fechada, o análogo especificado é: uma etapa com schema produz as perguntas, o run devolve um status de checkpoint, o chat coleta respostas, o run seguinte recebe as respostas em `ctx.args`. O texto de cada pergunta, se não for constante no código, continua modelo. O momento da pausa é o `return` do script.
- Inferência: chamar o MCP "certo" só é determinístico na escolha do servidor e da allowlist. A escolha da tool dentro do servidor permanece turno livre até existir um passo de código que fale com esse servidor sem agente. Esse passo não está na API do `ctx`.
